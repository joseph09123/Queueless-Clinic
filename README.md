# Queueless-Clinic

### Branching and Commit Message Convention

Our team agreed to use a shared GitHub repository with a simple branching and commit message convention to organize our development work.

**Branching Convention:**
- `main` – Contains the approved and stable project.
- `dev` – Used for combining and testing development work.
- `feature/name` – Used when developing new features.
- `fix/name` – Used when fixing errors or bugs.

**Commit Message Convention:**
- `feat:` – Adding new features.
- `fix:` – Fixing bugs or errors.
- `docs:` – Updating documentation.
- `style:` – Improving design or formatting.
- `test:` – Adding or updating tests.

All members must follow these conventions when creating branches and committing changes. Completed features will be reviewed before merging into the development branch.
